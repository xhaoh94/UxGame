### 编译错误修复：CS0759（partial 实现悬空）

用户过编译报 `UICodeGenWindow._OnInputClsNameChanged` CS0759 —— **Build 的 7 个主类里的 `_OnXxx` 是 `partial void` 实现，我漏了改 `private void`**（Timeline 改了，Build 忘了）。GenCode 的定义声明一删，这些实现就成"无定义的实现声明"。

- 修复：8 个文件（Build 7 个主类 + `VersionWindow_BuildRes.cs`）共 **77 处** `partial void _On` → `private void _On`。
- **顺带查实我漏注册的 2 个真 bug**：
  1. `VersionWindow` 的 `clear` 按钮：`_OnClearClick` 实现在**另一个 partial 文件** `VersionWindow_BuildRes.cs` 里 —— 只 grep 主类会误判"未实现"。

- 教训（可复用）：统计 C# 标识符别用 `[A-Za-z0-9]+`，要带 `_`；判断"方法有没有实现"要**在整个目录范围 grep**，不能只看主类文件。
- 交叉校验手段（本次新增，很有效）：对每个 `_OnXxx` **引用**，全目录 grep `void <name>(`，零悬挂才算过。

### 编译错误修复：CS0103 'Color' 不存在

`UICodeMemberItem.cs` 缺 `using UnityEngine;`（手搭时新用了 `Color`，但该文件原本只 `using UnityEngine.UIElements`）。已加。

- 教训：手搭会引入原文件没用过的类型（`Color`/`TextAnchor`/`FontStyle` = UnityEngine；`ObjectField`/`Toolbar*`/`MaskField` = UnityEditor.UIElements），**每改一个文件都要核 using**。
- 系统化检查命令（可复用）：遍历文件，若出现 `Color|TextAnchor|FontStyle|Mathf|Vector2|Vector3` 而无 `^using UnityEngine;`，或出现 `ObjectField|Toolbar|ToolbarButton|ToolbarMenu|MaskField` 而无 `^using UnityEditor.UIElements;`，就报出来。
- 命名空间归属实测（Unity 6000.4.3f1）：**引擎侧**（UnityEngine.UIElements）= IntegerField / EnumField / FloatField / DropdownField / ListView / Foldout / ScrollView / Toggle / IMGUIContainer；**编辑器侧**（UnityEditor.UIElements）= ObjectField / Toolbar / ToolbarButton / ToolbarMenu / MaskField。同时 `using` 两边不产生歧义（GenCode 原本就这么写且能编译）。

### 批量改路径的三个坑（都踩了）

1. **Grep 工具的搜索结果不可靠**：同一份代码，它漏报 `Assets/Editor/Build/**` 下的 3 个文件（`ConfigSettingData.cs` / `UIClassifySettingData.cs` / `VersionWindow_BuildRes.cs`）。批量操作前必须用**自写脚本全量扫描**核对。
2. **自写扫描脚本的 `SKIP_DIRS` 别乱加**：我把 `Build` 当构建产物排除 → 把 `Assets/Editor/Build/` 整个源码目录跳过了（少扫 4 处）。跳过目录只放**真实**产物目录（Library/.git/Temp/Logs/obj/bin/Bundles）。
3. **读写编码**：读用 `utf-8-sig` 会去 BOM，用 `utf-8` 写回**不会补回**，3 个带 BOM 的文件被抹掉。正确做法：`newline=''` 保留行尾 + 二进制读原始字节判断 BOM 后补回。校验脚本应对比备份的 BOM/CRLF/裸LF 数量。
