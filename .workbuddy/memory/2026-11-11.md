## HybridCLR 8.11.0 → 9.1.0
- **9.x 安装器改成精确匹配 minor**：版本表只有 2022.3.x / 6000.0.x / 6000.3.x，6000.4 直接 `NotSupportedException`。8.x 是 `versionParts[1] <= minor1` 就近回落，所以 6000.4 能装 6000.3 的 fork。**这是当初必须先把引擎降到 6000.3 LTS 的原因。**
- 命名空间大改：`HybridCLR.Editor.*` → `HybridCLR` / `HybridCLR.Meta` / `HybridCLR.CodeGen.AOT` / `HybridCLR.Utils` / `HybridCLR.Commands` / `HybridCLR.Installer`。
  `Analyzer` → `AOTReferenceAnalyzer`；**`MetaUtil` 在 `HybridCLR.Utils`**（8.x 在 `HybridCLR.Editor.Meta`）。
- `HybridCLRSettings` 删了 `hotUpdateDllCompileOutputRootDir` / `strippedAOTDllOutputRootDir` / `patchAOTAssemblies`；数据根目录从 `HybridCLRData/` 改成 **`Library/HybridCLR/`**。脚本 GUID 未变，`ProjectSettings/HybridCLRSettings.asset` 不用迁移（旧字段留着被忽略）。
- `Il2CppDef` 现在只产 `generated/UnityVersion.inc` + `AssemblyManifest.inc`。
- **Unity 进程内 `git clone` 会挂**：`Curl error 35 / schannel` 证书校验失败，`InstallDefaultHybridCLR()` 直接抛异常。绕过办法：在 bash 里 clone 到 `Library/HybridCLR/{hybridclr_repo,il2cpp_plus_repo}`，`mv hybridclr_repo/hybridclr il2cpp_plus_repo/libil2cpp/hybridclr`，再调 `InstallFromLocal("<...>/il2cpp_plus_repo/libil2cpp")`。
- **batchmode 下 `CompileDllCommand.CompileDll` 会卡死**：日志停在 `Require frontend run. Library/Bee/xxx.dag couldn't be loaded`，22 分钟只用 27s CPU。要跑 Player 编译只能开编辑器手动点，或用项目的 `VersionWindow_BuildDLL`。

## UI 调试面板栈列表取不到 UIData
- 现象：`获取不到UIData[1],请检查是否有注册UI`，由 `UIDebuggerStackItem.SetData` 触发。
- 根因：`UIMgr.FillUIStacks` 把 `StackEntry.RootId/ActiveId`（**实例 ID**，`_nextInstanceId` 从 1 开始）塞进 `UIStack.ParentID/ID`，而调试面板拿它当**类型 ID**（≥ `TypeIdBase=100000`）查 `GetUIData`。第一个界面实例 ID 正好是 1。
- 修复：`FillUIStacks` 改填类型 ID（`GetRecordTypeId(entry.RootId)` + `entry.ActiveTypeId`）；调试面板两处改为先 `IsHasUIData` 再取值，避免动态界面 UIData 已移除时刷错误日志/空引用。

## ECS 调试窗口只显示每层第一个子实体
- 现象：`EntityDebuggerWindow` 树里 `Map001(Clone)` 只列出 `CameraComponent_10`，玩家 `name_1`（Unit，Scene 的第二个子实体）看不到；右侧详情却写着「子实体：3」。
- 根因：`BuildNode` 递归时共用同一个成员 `_childrenBuffer`，`entity.GetChildren(_childrenBuffer)` 会 `Clear()` 后重填。递归进入子实体后外层列表已被清空，`for (i < _childrenBuffer.Count)` 立刻结束，于是每层只剩第一个可见子实体。
- 修复：改为按层深复用的缓冲池 `_childBuffers[depth]`（`ChildBuffer(depth)`），`BuildNode(entity, depth)`；详情面板用 `ChildBuffer(0)`。
- 注意：`BuildNode` 藏在编辑器窗口里，运行时无感；`EntityDebuggerWindow.cs` 本身是未跟踪的新文件（`Assets/Editor/Debugger/ECS/` 整目录 `??`）。

## ECS 调试窗口：组件与子实体分组显示
- 需求：树里组件（`CameraComponent_10`）和子实体（`name_1`）混在同一层，分不清。
- 实现：`EntityDebuggerWindow` 的树数据从 `TreeViewItemData<Entity>` 改成 `TreeViewItemData<TreeNode>`（`TreeNode` 是窗口内私有只读结构，`Entity == null` 表示分组节点）。
- 分组规则：**同一父实体下两种子节点都存在时**才插 `Component (n)` / `Entity (n)` 两个分组节点；只有一种就直连，避免多一层空壳。组件排在前面。
- **项目没有 `Component` 基类**（`CameraComponent : Entity`），只能按类型名后缀 `Component` 判断；改后缀的类会落到 Entity 分组。
- 分组节点加粗、选中时清空右侧详情（`OnSelectionChanged` 里 pattern match 解 `TreeNode`）。

## ECS 调试窗口：详情面板增加「定位」场景对象
- 判据：`Entity.Viewer != null`（`Link()` 时挂的 `EntityViewer`）；Unity 伪 null 天然覆盖组件被销毁的情况。
- 实现：`EntityDebuggerWindow.RebuildDetail` 在名称行后插一行「场景对象：xxx + 定位按钮」，点击 `Selection.activeGameObject = go; EditorGUIUtility.PingObject(go);`。
- 注意：只在 `RebuildDetail`（切选中/重建树）时生成，实体被 Link 后需重选才会出现按钮。

## ReflectInspector：自定义 struct（BoolValue）显示为类型名
- 现象：ECS 详情面板里 `Visible` 显示 `Visible: Ux.BoolValue`，且下面还有一条重复的 `<Visible>k__BackingField`。
- 根因：`ReflectView.BuildValue` 只处理基础类型/枚举/Unity 类型/集合/带 `[EEViewer]` 的 class，struct 落到兜底 Label（`ToString` 未重写 → 类型名）。
- 修复：新增值类型分支 → `BuildReadOnly` 递归成 Label/Foldout（列表最多 32 项、深度 4 层）；标题摘要取 struct 的 `Value` 成员（`DescribeValue`），`Refresh` 只更新标题。
- **值类型不回写**：反射拿到的是装箱副本，改副本落不到原对象，所以整棵子树只读，不生成输入控件。
- 另外在 `ReflectSpecs` 字段循环里跳过 `[CompilerGenerated]`，自动属性的 `<X>k__BackingField` 不再重复显示。

## BoolValue 改掩码（struct → sealed class）
- `HashSet<string> _tags` 换 `ulong _reasons`；`Set(string tag, bool v)` → `Set(ulong reason, bool v)`，**位由业务各自定义，不放统一枚举**（类型复用，集中枚举会逼所有模块共用一张位分配表）。
- 通知语义保持：只在 `0 ↔ 非 0` 翻转时回调；`Reset` 静默清零，`Release` 清零并断开回调。
- 顺带修掉旧实现的一个隐患：struct 属性返回副本，`Visable.Set(...)` 之所以生效全靠 `_tags` 是引用类型；换掩码后副本写入会**静默丢失**，改 class 才正确。
- 调试：类打 `[EEViewer]` → 反射面板展开成节点；`屏蔽位` 用只读十六进制 `ReasonMask`（可编辑的原始 `_reasons` 会绕过回调、让 Layer 与掩码脱同步，所以标 `[NonEEViewer]`）。
- **用 ulong 不用 uint**：位宽是这个类型的对外容量契约，改宽会让所有业务常量（`1u << n`）与已持久化的掩码值一起失效；x64/ARM64 上 64/32 位位运算同为单条指令，代价只有实例多 4~8 字节。附带避开 `1u << 32` 按 32 取模静默绕回 bit0 的坑。
