## UIType 与 UIWindow 的冲突

- 冲突根因：`Show()` 恒传 `checkStack=true`，`CommitVisible` 只跳过 `Fixed`，而 `UIWindow` 默认 `Normal` ⇒ 窗口会进 `_stackEntries`；`Hide` 里又会 `PeekPrevious` 把上一个界面重新 `_ShowAsync`（页面本来就可见）⇒ `ToOverwrite` + `UI_SHOW` 重发。多个窗口时关中间那个会把最上层再刷一遍。
- 枚举收敛成两个值（原 `Normal`/`Stack` 在实现里行为完全相同，`Fixed` 的"始终显示在最顶层"是假注释）：
  - `UIType.Stackable`（参与栈，全屏页面，默认）
  - `UIType.NonStackable`（弹窗/飘字/窗口）
- `UIStackHandler.CommitVisible` 改成 `if (type != Stackable) return;`：以后加枚举值默认不进栈。
- **只改 Type 不够**：`_Hide` 的回退只看 `checkStack`，跟"这个界面在不在栈里"无关。`RemoveRoot` 改为返回 bool，`_Hide` 用 `removedFromStack && checkStack` 才回退 —— 顺带修掉"关弹窗也把下面的页面重刷一遍"。
- `UIWindow.Type => NonStackable`；`BagWindow` 里原有的 `override UIType Type => Normal` 必须删掉，否则又把窗口的声明覆盖回去。

## RendererFeature 模糊全黑（Unity 6 RenderGraph）

- 根因不是 shader：`UIBlurRendererFeature` 在 `SetRenderFunc` 的 lambda 里调 `context.cmd.SetGlobalVector`，raster pass 默认禁止改全局状态 → `InvalidOperationException: Modifying global state ... not allowed` → `RenderGraph.ResetGraphAndLogException` **重置整张图**，Base 相机那一帧什么都没画（Game 视图只剩 Overlay UI 可见，背景纯黑）。

## 虚拟列表分批生成

- `UIVirtualListComponent` 新增 `IncrementalCreate` / `BatchSize`(4) / `BatchIntervalMs`(33) / `InitialCount`(-1=自动) / `FrameBudgetMs`(0) + `IsFilling` / `PendingCreateCount` / `FillingCompleted`。
- 核心在 `UIVirtualList`：`SyncVisibleItems` 拆成「收集缺失 + `CreateItem`」，首次填充时把缺失项**按索引升序**（从上到下）入队；`InitialCount` >0 先同步建这么多，`0` 首帧不建（等一个批次间隔），`-1`（默认）跟随每批数量且首批立即执行（`_forceNextBatch = InitialCount < 0`）。宿主 `LateUpdate` 调 `TickPendingCreate()` 按批次补。

- 动态尺寸：未创建项由 `UIFlowLayout` 的 `DefaultMainSize` 占位，创建后 `Measure` 修正，滚动锚点沿用现有机制。

- **编译期红线 `UXRES001`**：`Tools/Analyzers/Ux.Analyzers/ResLoadGameObjectAnalyzer.cs`，`ResMgr.LoadAsset<GameObject>` / `LoadAssetAsync<GameObject>` 直接报 Error。
- 分析器工程**原来没有 .csproj**（路径还指向旧的 E:\），已补 `Ux.Analyzers.csproj`（netstandard2.0 + Microsoft.CodeAnalysis.CSharp 4.10.0）；`dotnet build -c Debug` 后把 dll 拷到 `Assets/Settings/Analyzers/`。
- 分析器工程从 `Ux.EventAnalyzers` 改名为 `Ux.Analyzers`：目录、AssemblyName、命名空间（两个 analyzer 统一 `Ux.Analyzers`）、dll 名、`/analyzer:` 路径全部同步；旧 bin/obj 一起清掉了（它们本来被 git 跟踪，会显示为删除）。
- **`csc.rsp` 里的路径原来是错的**：写着 `Assets/Analyzers/Ux.EventAnalyzers.dll`，该目录不存在 —— 也就是说 `UXEVT001` 之前很可能一直没生效。现在指向 `Assets/Settings/Analyzers/Ux.Analyzers.dll`。
- **但 csc.rsp 这条路根本走不通**：Unity 只读 `Assets/csc.rsp`（仅覆盖 Assembly-CSharp 等预定义程序集）或 asmdef 同级目录的 rsp（仅覆盖该程序集）。`Assets/Settings/Analyzers/csc.rsp` 两个条件都不满足，从未被读取；就算放到 Assets 根目录也覆盖不到 `Unity.HotfixBase` 里的代码。
- **最终方案：给 dll 打 `RoslynAnalyzer` 标签**（meta 顶层 `labels: - RoslynAnalyzer`），Unity 2020.2+ 会对所有程序集生效，不依赖 rsp。rsp 内容已注释掉，仅留说明。
- **analyzer dll 的 `.meta` 必须是「禁用的 PluginImporter」**（`platformData` 里 Any/Editor 都 `enabled: 0`、`validateReferences: 0`），否则会报 "Unable to resolve reference 'Microsoft.CodeAnalysis'"。改完 meta 要 Reimport 才生效。
- **analyzer 必须按 Unity 内置 Roslyn 版本编译**：6000.4.3f1 是 **4.3.0**。用 4.10.0 编出来的 dll 会触发 `warning CS9057`，Unity 直接不加载它（只在 IDE 里报错、Console 什么都没有）。包引用固定 `Microsoft.CodeAnalysis.CSharp 4.3.0`，编译后可用 `PEReaderExtensions.GetMetadataReader` 核对引用版本。
