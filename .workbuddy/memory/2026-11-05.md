## Window 系统审查修复（P1-1/3、P2-4~9）

- **遮挡重算的时机**：`UIWindow` 里必须放在 `RemoveToStage` 覆写里，不能放 `ToHide` —— 带隐藏动画时 `Visible` 要到 `RemoveToStage` 才翻 false，早算等于没算（下层窗口 Canvas 仍关着 = 一片空白）。
- **布局坐标基准唯一入口** `UIWindow.LayoutSpace`（= `BodyRect.parent`）：`GetStageRect` / `CaptureRect` / `ApplyRect` / `GetMaximizeRect` / `ToAnchoredPosition` / `UIWindowDrag` / `UIWindowResize` 全改走它；`AddToStage` 里 `ValidateStageRoot()` 比对它与 `UILayer.Window` 容器 rect，不等就报错（比例会静默偏，不抛异常）。
- **超限未注册的窗口**（`Register` 返回 false）：`_hasInstanceSlot = false` ⇒ 读写布局存档全跳过，否则 `GetSlot` 恒 0 会覆盖同类首个窗口存档。
- **激活去重**：`UIStageHandler.IsLastInTier` → `UIWindowService.Activate` 已在 Tier 末尾时跳过 `Promote + RefreshOcclusion`（拖动时每次 pointer down 都会走 Activate，Promote 是整层重刷）。
- **RefreshOcclusion** 改为预计算 `OcclusionItem{Window, Order, Area}` 再排序；Order 直接读 `UIBase.StageSortingOrder`（原来是比较器里调 `TryGetStageSorting`，O(n log n × k)）。顺带删掉已成死代码的 `IWindowHostAccess.TryGetStageSorting` 与 `UIMgr.TryGetStageSorting`。
- **`UIStageHandler.TierCount`** 由枚举成员数推导：`private static readonly int TierCount = Enum.GetValues(typeof(UIWindowTier)).Length;`（枚举值必须从 0 连续）。
- **`UIWindowDrag.Enabled`** 只管拖动；新增 `ActivateOnPointerDown` 单独控制点击置顶。
- **最小化不是隐藏**：`Visible` 仍为 true。`GetTopmost` 过滤 `Minimized`；`CycleWindow` 切到最小化窗口要先 `Restore()` 再 `BringToFront()`。
- 未做（用户明确排除）：P1-2（`IWindowObserver` 开/关事件时机）、P2-10（`Release()` 清 `_windowObservers`）。

## 补做 P1-2：开/关事件挪到 Show/Hide

- 语义拆分：**注册表**（`Register/Unregister`）= 实例生命周期（LRU、实例槽位、布局存档键）；**业务事件**（`WindowShown/WindowHidden`）绑定 `AddToStage/RemoveToStage`，不再在 Register 里发。
- `UIWindowService._shownIds`（HashSet）保证开/关成对：重复上屏不重发；未登记实例（None 能力 / 超限）不发事件，与 `FillWindows` 一致。
- `UIWindow.OnDispose` 里补一次 `NotifyHidden`，覆盖「还没 Hide 就直接销毁」的路径。
- 淘汰顺序改成**先 Hide 再 Unregister**：事件挂在 Hide 上，反过来会先删条目导致关窗事件发不出去。
- 遗留：`FillWindows` 仍返回已关闭的缓存实例（切换器要靠它把窗口重新 Show 出来），任务栏请按事件自己维护，或在业务侧过滤 `Visible`。P2-10 保持现状（Release 清观察者被视为正常）。

## UIType 与 UIWindow 的冲突

- 冲突根因：`Show()` 恒传 `checkStack=true`，`CommitVisible` 只跳过 `Fixed`，而 `UIWindow` 默认 `Normal` ⇒ 窗口会进 `_stackEntries`；`Hide` 里又会 `PeekPrevious` 把上一个界面重新 `_ShowAsync`（页面本来就可见）⇒ `ToOverwrite` + `UI_SHOW` 重发。多个窗口时关中间那个会把最上层再刷一遍。
- 枚举收敛成两个值（原 `Normal`/`Stack` 在实现里行为完全相同，`Fixed` 的"始终显示在最顶层"是假注释）：
  - `UIType.Stackable`（参与栈，全屏页面，默认）
  - `UIType.NonStackable`（弹窗/飘字/窗口）
- `UIStackHandler.CommitVisible` 改成 `if (type != Stackable) return;`：以后加枚举值默认不进栈。
- **只改 Type 不够**：`_Hide` 的回退只看 `checkStack`，跟"这个界面在不在栈里"无关。`RemoveRoot` 改为返回 bool，`_Hide` 用 `removedFromStack && checkStack` 才回退 —— 顺带修掉"关弹窗也把下面的页面重刷一遍"。
- `UIWindow.Type => NonStackable`；`BagWindow` 里原有的 `override UIType Type => Normal` 必须删掉，否则又把窗口的声明覆盖回去。

## RendererFeature 模糊全黑（Unity 6 RenderGraph）

- 根因不是 shader：`UIBlurRendererFeature` 在 `SetRenderFunc` 的 lambda 里调 `context.cmd.SetGlobalVector`，raster pass 默认禁止改全局状态 → `InvalidOperationException: Modifying global state ... not allowed` → `RenderGraph.ResetGraphAndLogException` **重置整张图**，Base 相机那一帧什么都没画（Game 视图只剩 Overlay UI 可见，背景纯黑）。
- 修法：render func 里只做 blit；`_UIBlurTex_TexelSize` 改由 `UIBlurHandler.ShowBackdrop` 按 `Shader.GetGlobalTexture("_UIBlurTex")` 的实际尺寸写进材质（全局纹理不会自动带 `_TexelSize`，不设则 9 个采样点全落在中心）。
- 排查入口：`%LOCALAPPDATA%\Unity\Editor\Editor.log` 搜 `InvalidOperationException` / `ResetGraphAndLogException`。
- 遗留风险：`SetGlobalTextureAfterPass` 用的是 RenderGraph transient 纹理，跨相机（Base→Overlay UI）不保证存活；若出现模糊内容为上一帧/花屏，改成自己 Alloc 的持久 RTHandle + `renderGraph.ImportTexture`。

### 没有场景相机时 RendererFeature 必然黑

- `UIBlurRendererFeature` 显式跳过 `[UICamera]`（它只画 UI，不透明纹理是空的），所以 UI 相机自持 Base 时 `_UIBlurTex` 根本不存在 → `ShowBackdrop` 降级成 0.55 黑遮罩 → 看起来"模糊没生效、黑底"。
- `UIBlurHandler.ResolveCaptureMode`：声明 `RendererFeature` 但 `!_manager.HasSceneCamera || 全局纹理为 null` 时，实际按 `RenderTexture` 走 —— 即 `PrepareBeforeShowAsync` 在帧末把 `BlurCaptureCamera` 渲染到半分辨率 RT（能截到 UI 自身）。
- `UIMgr.HasSceneCamera` = `StageHost != null && isActiveAndEnabled`。
- 两种相机形态自动切换：有场景 Base → Feature 采场景；只有 UI → 显示前截图。注意"截图"截的是**打开窗口之前**的整屏，背后本来就是黑的话，模糊出来仍是黑。
- 顺手加了保护：`PrepareBeforeShowAsync` 对 `Visible == true` 的界面不截图，否则重复 Show 会把窗口自己截进背景。
