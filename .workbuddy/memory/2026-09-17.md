## 战斗模块：Timeline 阶段不再扫全场（落地"方案 B"）

**背景**：用户提出"把 FrameEvents 拆成 hitEvents，让 Hitbox 只遍历自己关心的表"。讨论后确认拆表性能收益是纳秒级（M = 本帧出招单位数，跳过一项的成本是 2-4ns），而更值得做的是让 Timeline 阶段免掉一次全场扫描。

**改动**（3 个文件，行为等价）：

| 文件 | 改动 |
|---|---|
| `BattleWorld.cs` | 新增 `_actionActive` 字段 + `ActionActiveEntities` 只读视图；`PhaseActions` 在 `TickLogic` 之后收集 `HasAction` 的实体 |
| `CombatTimelineSystem.cs` | 遍历源从 `OrderedEntities` 换成 `ActionActiveEntities`；去掉 `IsCombatActive` 检查（已由 Actions 阶段筛过），保留 `Id <= 0` 与 `HasAction` 检查 |
| `COMBAT_DESIGN.md` | 阶段交接表加 `ActionActiveEntities`，并说明它是唯一"由生产者自己复位"的缓冲 |

**核心设计**：索引要建在已经付过遍历成本的地方。`PhaseActions` 本来就在遍历 `_ordered`，且它在 Timeline 阶段之前；起手/取消/结束全发生在 `TickLogic` 里，所以它返回时 `HasAction` 就是本帧权威事实。总遍历从 2N 降到 N，且不需要 Runner 回调 / 脏标记 / 注册注销路径（后者会引入漏改静默失效的口子）。

**不能做的事**：把 Timeline 并进 Actions 阶段——那会拆掉阶段屏障（"所有单位推进完状态，才开始求值"），退回单位优先。

**唯一的语义差异**：`IsCombatActive` 的检查时机从 Timeline 阶段移到了 Actions 阶段末尾。若有 Timeline 插件（Order < 0，即 `CombatTimelineSystem` 之前跑）在帧中途改 `IsCombatActive`，行为会不同。当前无此类插件，已写进 `ActionActiveEntities` 的注释。

**验证**：28 个 Combat 文件剥注释+字符串后 `{}`/`()`/`[]` 全平衡；`ActionActiveEntities` 恰好 1 处定义 1 处消费；`OrderedEntities` 剩余 3 处消费点（Hitbox 目标收集 / Buff / Death）都确实需要全场。测试全部经 `world.Tick` 走完整 `TickFrame`，无绕过插件直调的写法；`StubEntity.Controller` 恒非 null。**仍未编译**（沙箱 `dotnet restore`/`csc` 被拦）。

**行为等价的验证方式**：跑一场战斗，`[Hitbox] frame=... A → B ...` 日志应逐行一致。

## 目录重组：Runtime/ 按职责拆四层

`HotfixBase/Manager/Combat/Runtime/` 下 18 个源文件原来平铺，按职责拆成四层：

| 目录 | 文件数 | 内容 |
|---|---|---|
| `Core/` | 5 | BattleWorld / BattlePhase / ICombatEntity / BattleWorldSnapshot / CombatStageBuffers |
| `Unit/` | 6 | CombatController / UnitStateMachine / CombatActionRunner / StateSnapshot / AttributeSet / CombatBuff |
| `Systems/` | 6 | 5 个阶段插件 + CombatHitResolution |
| `Presentation/` | 1 | CombatTimelinePlayer |

- 命名空间统一是 `Ux` → **纯挪目录，零编译影响**
- `.cs` + `.cs.meta` 成对移动，移动前后 36 个文件 md5 完全一致 → **GUID 不变，引用不断**
- 新目录 `.meta` 照 `Runtime.meta` 格式生成（CRLF），GUID 在全项目 2172 个 meta 中去重
- 引用链复核：Combat 的 27 个脚本里只有 `Asset/CombatActionAsset.cs` 与 `CharacterCombatProfile.cs` 被资产引用（各 2 处）；**Runtime 下全是纯代码类，无任何资产引用**。全项目 58 个悬空 `m_Script` 引用全是 URP / TMP / DebugConsole / Astar 的包内脚本，与 Combat 无关
- 重命名检测（临时索引 `GIT_INDEX_FILE` + `git add -A` dry-run）：**36 R + 4 A**，git 历史保留
- `COMBAT_DESIGN.md` 同步：修正 7 处旧路径 + 新增「代码目录结构」小节；该文档是 **CRLF**，插入段落引入的 39 行 bare LF 已统一回 CRLF

**行尾是既存状况，非本次引入**：仓库 `core.autocrlf=true` 但无 `.gitattributes`，工作区本就混着 LF / CRLF（`git add` 会警告 `LF will be replaced by CRLF`）。本次移动未改变任何字节。

**新踩的坑**：bash heredoc 把 `\s` 转成 `/s`，导致第一版 GUID 校验脚本静默返回空结果（`re.search` 返回 None 但不报错）。含正则的 Python 一律先 Write 成 `.py` 再执行。
