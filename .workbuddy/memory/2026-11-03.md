## UI 资源分类重构（模块 → 归类）
- 数据模型 `UIClassifySettingData.modules[]`（模块名 → tag）：**没配置的模块默认 preload**；tag 空也按 preload；其余即 builtin 或下载标签。窗口：内置(builtin) / 懒加载(目录+标签) 两个手动列表；目录用 **DropdownField**（选项来自扫描 `path` 下的目录），顶部 `TextField` 搜索框过滤下拉选项（已选值即使不匹配也保留），「刷新目录」重扫，新增行自动选中第一个未占用的模块。
- 收集器由 `UIClassifyWindow.CreateYooAssetUIGroup` 生成，共 **3 + L 条**（L = 打了 lazyload 标签的模块数）：① `CollectAtlasSource` 全局图集源图（只收 /Atlas/ 下 png，**StaticAssetCollector**）；② `CollectBuiltinModule` 全局 builtin 合并；③ `CollectPreloadModule` 全局 preload 合并（含没配置的模块）；④ 每个 lazyload 模块一条 `CollectModuleMain`。三个合并收集器靠 `UIClassifySettingData.GetAssetTag(assetPath)`（取所属模块名 → 查配置 → 未配置 = preload）分流，必须互斥否则重复收集报错。地址规则 `AddressByGroupOrAtlas`：图集本体 `Atlas_文件名`，其余 `组名_文件名`。
- 新增地址规则 `AddressByAtlas` → `Atlas_{文件名}`，避开与同名 prefab 的 `UI_{文件名}` 冲突。
- 旧过滤器 `CollectBuiltinUI`/`CollectPreloadUI` 删除；旧收集器配置在点一次“生成配置”（或走 `UxEditor.Export`）前是失效状态。

## 资源句柄持有（ResRef / UIImage）
- 新增 `HotfixBase/Manager/Res/ResRef.cs`：`ResRef<T> : IDisposable`，持 `AssetHandle` + `Asset`，`Dispose()` 释放。用 class 不用 struct（struct 复制后会重复 Release）。
- `ResMgrLoad` 新增 `LoadAssetHandle(location, resType)` 与 `LoadRef<T>(location, resType)`；**没动** `LoadAsset<T>` 的 `using (handle)` 分支（"用完即弃"语义，适合 TextAsset 之类）。
- 新增 `HotfixBase/Manager/UI/Component/UIImage.cs`：`UIObject` 子类（不是继承 Image），`SetSprite(address)` 散图 / `SetSpriteFromAtlas(atlasAddress, spriteName)` 图集 / `SetSpriteReference(sprite)` 不持句柄；`ReleaseAll()` 在换图和 `OnDispose` 里调。
- **GameObject 路径保持 ResHandleMono 不变**：句柄由实例持有、OnDestroy 释放，正好配合 UnityPool（池里的实例不能释放句柄）。换成 ResRef 会把 Dispose 责任推给每个调用方并让池子还得存 handle，是倒退。
- 补了异步版：`LoadAssetHandleAsync` / `LoadRefAsync<T>`。`HandleBase.ToUniTask()` 失败时是抛异常（`OperationHandleBaseExtensions.cs:175`），所以 await 外层 try/catch 里必须 `handle.Release()` 再 rethrow，否则失败的句柄会一直占着包引用。
- `UIImage` 补齐异步换图：`SetSpriteAsync` / `SetSpriteFromAtlasAsync`。异步必须带版本号（`_requestVersion`）防竞态：列表快速滚动时先发的请求可能后回来，不校验就会把新图覆盖回旧图；`OnDispose` 里 `++_requestVersion` 让在飞的请求作废并自行 Dispose 句柄（否则销毁后回来的句柄无人释放）。同步版保留，资源已驻留时它没有 await 开销。
- **修正：`ResRef<T>` 已删除**（`ResRef.cs` + meta 一并删）。理由：`HandleBase : IDisposable`、`Dispose()` 就是 `Release()`，`using (var h = ResMgr.LoadAssetHandle(...))` 原生可用；ResRef 只是把 `GetAssetObject<T>()` 缓存一层 + 一个 `Asset` 属性，多余。`LoadRef/LoadRefAsync` 同步删除。`UIImage` 改为直接持 `AssetHandle` 字段，换图/Dispose 时 `Release()`。
- `HandleBase.Release()` 是幂等的（释放后 `Provider = null`，第二次走 `IsValidWithWarning == false` 直接 return），所以重复 Release 不会崩——但别依赖它来兜底逻辑。
- `PathHelper.Res` 对齐当前地址规则：`UI = "UI_{0}"`（原 `UI_{0}_{1}` 是 FGUI 时代残留）、新增 `Texture = "Texture_{0}"`、`Atlas = "Atlas_{0}"`；删除未使用的 `UIAtlas`。`UIImage` 外部接口改为只传名字：`SetSprite(图片名)` → `Texture_名字`，`SetSpriteFromAtlas(图集名, sprite名)` → `Atlas_图集名`。

## SSC 迁移 + 模型直挂 UI（已实现，待 Unity 验证）
- **相机**：URP 按 `camera.depth` 升序渲染（UniversalRenderPipelineCore.cs:1470）。`EnsureUICameras`：`[UICamera]`(Overlay, ortho, near **-50**/far 200, mask=UI+UIModel) + `[UIPatchCamera]`(Base, mask Nothing, 黑背景, depth **-100**)；进场景后 `CameraComponent.OnAwake → UIMgr.AttachUIStack(mapCamera)` 把 UI 相机挂进场景栈；`EnsureStackHost`（GameMethod.Update）在宿主被场景卸载销毁后挂回兜底栈。场景相机 depth 必须 > -100。
- **根 Canvas**：Overlay → **ScreenSpaceCamera** + worldCamera（UIMgr.ConfigureRootCanvas）。PatchView 预制自带 SSC canvas（worldCamera null = 表现同 Overlay），不受影响。
- **层内排序**（对齐参考项目 WndBase）：层容器无 Canvas；每个界面 `AddToStage → UIBase.AttachStage(layer) → UIMgr.RegisterStage`：根节点挂 `Canvas(overrideSorting)+GraphicRaycaster`，sortingLayer = 层固定（UI_Bottom…UI_Top 六个），order = 100×层内显示序号，**Show/Hide 时经 RefreshLayerOrder 重排**（隐藏窗口 order 不动）。子页面（UITabView）挂父级，不参与。
- **重排触发**：RegisterStage/UnregisterStage（AttachStage/HideInternal/OnDispose 调用）；RefreshLayerOrder **必须走 GetRecord 不能走 _showed**（RegisterStage 发生在可见提交之前，走 _showed 新窗口 order 恒 0——已踩）。
- **模型直挂**：`UIModel` 改造——模型 layer → 新 object layer **`UIModel`**（工具插到 index 11；UICamera mask 含它、场景相机默认不含 ⇒ 不双渲染；不用 RTModel 层防双渲染）、挂 `SortingGroup`（sl=父界面 sl，order=父界面 order+50，`OnStageSortingChanged` 联动重排）、材质实例 `renderQueue=3000`（opaque 不进透明排序队列，这是硬前提）、localPosition z=-1（Canvas 平面在相机前 100）。
- **UI 对象层**：UICamera 按 layer 裁剪，而预制 UI 全在 Default 层 → `UIBase.CreateGameObject` 加载后递归 `SetLayer(UI)`；UIRoot/backdrop 同样。
- **BlurBackdrop**：加了自己的 Canvas+GraphicRaycaster（否则被所有界面 canvas 压住）；sl=触发窗口 sl、order=窗口 order−50，`RefreshBackdropSorting` 在 OnShowed/重排后对齐。
- **编辑器工具**：`UxGame/工具/UI/初始化 UI SortingLayer`（UISortingLayerTool，Editor/UI/Build/）——幂等插 6 个 SortingLayer（Default 之后）+ UIModel object layer。**必须先跑它**，否则 canvas.sortingLayerName 指向不存在的层会静默失效。
- 待验证：Patch 界面、进 Map001 世界+UI、点击、blur、模型直挂排序、动画、多分辨率。
- 编译修正：URP 17 的相机栈属性是 `cameraStack` 不是 `stack`；`clearDepth` 只读（序列化默认 true，正合需求）。
- 动态子物体 layer：SSC 下 UICamera 按 layer 裁剪，prefab 对象默认 Default 层。`UIVirtualList.Create` 的 Instantiate 后补 `SetLayer(UI)`（虚拟列表是唯一的运行期 item 创建点）；今后任何"stage 之后再往界面下挂 prefab 实例"的代码都要手动 SetLayer(UI)，否则 UICamera 看不见。
- **首验失败修复（UI 不显示）**：根因不是 SSC 本身——`AttachUIStack` 只挂在 `CameraComponent.OnAwake`，但它只在 `EnterScene` 时跑；登录阶段没人挂栈，且 Hotfix 场景里活跃的相机（depth 0）在 PatchBase(-100) 之后渲染并 clear，把 UI 全清掉。修复：① `EnsureStackHost` 改成每帧在「宿主=兜底栈」状态下用 `Camera.GetAllCameras` 扫描已激活 Base 相机并迁移（`Camera.allCameras` 会分配数组，用 count+buffer）；② `CameraComponent.OnAwake` null-safe（mapCamera 未激活时 Find 返回 null，原代码 `.GetComponent` 直接 NRE——这是历史遗留，现在找不到就等 EnsureStackHost 自动挂）。
- **`[UIPatchCamera]` 已删除**：查证项目没有加载界面、PatchView 自带 Canvas，兜底相机兜的是一个不存在的场景。现在只有 `[UICamera]`(Overlay)：`EnsureStackHost` 每帧在「无宿主或宿主被销毁/禁用」时扫描 `Camera.GetAllCameras` 找激活的 Base 相机挂上去，找不到就 `_stageHost = null`（UI 不渲染，无兜底）。宿主判活用 `isActiveAndEnabled`，被禁用的宿主也会触发重挂。
- 生命周期收口（用户反馈后调整）：`AddToStage` 保持 virtual（UITabView 要改成挂父级），基类实现 = 挂层 + SetActive + `RegisterStage`；子类只声明 `StageLayer`。`RemoveToStage` 改 **private**（隐藏 GameObject + `LeaveStage` 注销），原先 `UIWindow` 那个与基类一字不差的 override 已删——它是当初不敢把注销放进 RemoveToStage 的唯一原因。`LeaveStage` 仍在 `OnDispose` 保留一份兜底（UIMgrHide.cs:687 的"旧实例回收"直接 Dispose，不走隐藏提交）。
- `CallbackData` 已删除：`IUI.InitData(IUIData, IUICallback, int)` 直接把接口传进界面，`UIBase._callback` 存它；`UIMgr._initData = this`。**`IUICallback` 必须是 public**（public 的 `IUI.InitData` 签名不能用 internal 类型，CS0051），但 UIMgr 全用显式实现，方法不在 `UIMgr.Ins` 的公开 API 上。`IUIBlurHandlerCallback` 已并入该接口并删除。
- **UI 相机/排序拆成两个 handler**：`UICameraHandler`（创建 UICamera + Overlay 设置 + `Attach` + `TryAttachAny`，114 行）、`UIStageHandler`（`Dictionary<UILayer, List<UIBase>>` + Register/Unregister/Refresh/TryGetSorting + `ModelOffset=50`，118 行）。UIMgr 只剩转发，降到 1186 行。
- **删掉每帧 tick**（`GameMethod.Update += EnsureStackHost` 已移除）：改为三个确定性时机触发挂栈——① UICamera 创建时 `TryAttachAny()`；② 场景加载 `CameraComponent.OnAwake → UIMgr.AttachUIStack(mapCamera)`；③ 任一界面首次上屏（`IUICallback.RegisterStage` 里先 `_cameraHandler.TryAttachAny()`）。宿主有效时 TryAttachAny 只做一次 `isActiveAndEnabled` 判断。
- `UIStageHandler` 表里直接存 `UIBase`（只有已上屏界面在表里），不需要回查 UIMgr，因此无 callback 依赖；`ModelOffset` 从 `UIMgr` 挪到这里，UIModel/UIBlurHandler 引用同步改。
- `UISortingLayerTool` 的层名已与代码对齐成 **sl1~sl6**（用户手动改过代码，原工具还在插 UI_Bottom…UI_Top，会静默失效）。
