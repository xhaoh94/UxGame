# 2026-11-04

## UI 相机双形态（UICameraHandler）
- 之前 UI 相机固定 Overlay，没有宿主时什么都不画（黑屏）。现在改成两态：
  - **无场景相机 → 自持 Base**：`clearFlags = SolidColor` + 黑背景、`depth = -100`、cullingMask 只有 UI+UIModel，自己出画面。
  - **有场景相机 → 切 Overlay**：`Attach(base)` 里先把 `renderType` 切成 Overlay 再入栈（**Base 相机放进别人 cameraStack 会被 URP 忽略**，顺序不能反），`clearFlags = Nothing`、`depth = 100`。
- 切换时机仍是三个确定性点，不每帧轮询：`EnsureCamera` 末尾 `TryAttachAny()`、场景加载 `CameraComponent.OnAwake → AttachUIStack`、界面首次上屏 `IUICallback.RegisterStage` 里 `TryAttachAny()`。
- `TryAttachAny` 扫不到 Base 相机时调 `ApplySelfHosted()` 回落到 Base（原来只是 return false，什么都不做）。
- 已知边界：世界相机出现但还没走到上面三个时机的那几帧里，自持 Base 会在世界之前画（depth -100），世界相机 clear 覆盖 ⇒ UI 短暂不可见；下一帧相机就绪/界面刷新即恢复。
- `Camera.allCameras` 现在会包含自持状态的 UI 相机本身，扫描时用 `cam == _uiCamera` 排除。

## Sorting Layer / Order 不生效（用户截图反馈）
- **Order in Layer 恒 0**：`UIBase.ApplyStageSortingOrder` 重构时只写了 `StageSortingOrder` 字段 + 通知组件，**没有任何代码写 `Canvas.sortingOrder`**。已补：`UIBase` 新增 `internal Canvas StageCanvas`（`UIStageHandler.Register` 里写入），重排时同时写 `StageCanvas.sortingOrder = order`。
- **Sorting Layer 落回 Default**：`canvas.sortingLayerName = "sl3"` 解析成 ID 0 就是 Default。两个原因：① 截图时（16:22）工具还没跑（Editor.log 显示 16:25 才插入 6 个层）；② 工具用 `string.GetHashCode()` 写 `uniqueID` —— .NET Core 下**每进程随机**，且 sl5/sl6 实际写成了 0（和 Default 撞 ID）。
- 工具已改：`NextId()` 用 FNV-1a 生成稳定非零 ID + 冲突自增；启动时**修复已有条目的 0 ID**；保存后 `VerifySortingLayers` 校验重名/0/重复；最后 `LogEffectiveLayers` 打印 Unity 实际生效的层列表（改 TagManager 可能要重载编辑器才刷新）。
- `UIStageHandler.Register` 加了运行时报错（只报一次）：层名解析不到时提示跑工具 + 重启。
- UI 代码生成目录忽略 `Prefab` 段：`UIPrefabCodeGenerator.GetOutputDirectory` 现在按 `/` 拆开相对路径、丢掉名为 `Prefab` 的段再拼。`Res/UI/Common/Prefab/Common1TabFrame.prefab` → `Assets/Hotfix/CodeGen/UI/Common/Common1TabFrame.cs`。命名空间仍是固定的 `Ux.UI`（不随目录变），所以不用改引用。
- UI 绑定代码菜单支持**选中文件夹批量生成**：`UICodeGenWindow.OpenFromContextMenu` 先判 `AssetDatabase.IsValidFolder`，是目录就 `GenerateFolder()`（递归 `*.prefab`，逐个 `MergeWithSaved + Scan + GenerateConfigured`，不弹窗口），失败逐条 `LogError` 并弹汇总；选中单个 prefab 仍走原面板。`_namespaceName` 固定 `Ux.UI`，批量时同理。
- **代码生成统一出口**：新增 `Editor/CodeGen/CodeFileWriter.cs`（`Ux.Editor` 命名空间）：UTF-8 无 BOM、换行归一成 LF、内容相同就跳过写入（返回 bool）。`UIPrefabCodeGenerator` 改为 `CodeFileWriter.Write`，日志区分“生成成功 / 无变化跳过”。
- 删除 `Editor/CodeGenWrite.cs`(+meta)：早已 0 引用，且 `Export` 用 `Encoding.UTF8` 会写 BOM，和生成器约定的无 BOM 冲突；文件在 git 里有记录，需要可回滚。

- **补上代码排版层 `Editor/CodeGen/CodeBuilder.cs`**：`Line(text)`（自动按当前缩进）、`Open(header)` / `Close(suffix)` 维护层级、`Blank()`（连续空行去重）、`Indent/Unindent`。`UIPrefabCodeGenerator.BuildCode` + `BuildChildExpression` 已全量改用 `cb.Line/Open/Close`，源码里不再出现手写缩进空格。

- 注意：现有 `CommonDialog` 生成的 6 个 override 会在下次重新生成时消失（UIDialog 的这些属性是 virtual，不会编译报错，是运行期静默失效）——必须先在新面板里选好 6 个槽位再生成。
- UITabFrame 也接入同一套：`EmitSlot` 输出 `__listTab/__tabContent/__btnClose`，不再按名字猜；窗口按 `_baseType` 切槽位表（DialogSlots / TabFrameSlots）。**UITip 仍保留名字推断**（还没做选择区）。
- **UI 代码生成菜单不认左树目录的根因**：Unity 6 的 Project 左树只是「导航状态」，右键时 `Selection.objects` 是**空的**（菜单项因此置灰）；只有右键右侧资源区才会写 Selection。修法：`CollectSelection` 在 Selection 为空时退回 `ProjectWindowUtil.GetActiveFolderPath()`（当前打开的目录），随后走批量生成。选中非 prefab 资源时不回退，菜单保持置灰。
- `ProjectWindowUtil.GetActiveFolderPath()` 在 Unity 6 里是 **internal**（CS0117），只能反射调用；封装成 `GetActiveProjectFolder()`（缓存 MethodInfo + try/catch）。回退还加了 `IsProjectWindowFocused()`（`EditorWindow.focusedWindow` 类型名 == `ProjectBrowser`），否则在别的窗口点顶部 Assets 菜单会拿到 `"Assets"` 当目录，扫全工程。
- 代码生成窗口列宽自适应：`CalcColumns(position.width)` 按基准宽（330/150/170/220）等比缩放四个可伸缩列（节点/类型/字段名/事件），并设最小宽（200/110/130/150），仍放不下就整体压缩；「规则」「生成」保持固定 64/44。`_columns` 在 OnGUI 开头算一次，表头与行共用。
- 生成列右侧空白：`CalcColumns` 预留从 30 改成 16（一个滚动条宽），表头「生成」用 `ExpandWidth(true)` 撑到右边界，行内勾选框宽取 `Mathf.Max(38, row.xMax - x - 4)`，无滚动条时也不会留白。
- 生成代码窗口对齐：表头 toolbarButton 居中而内容左对齐导致偏左——「规则」改用 `EditorStyles.centeredGreyMiniLabel`，勾选框按 `(列宽-16)/2` 居中。
