# 2026-11-12

## 虚拟列表：Item 绘制顺序（RenderOrder）

`UIVirtualList` 新增 `UIVirtualListRenderOrder`：`Unmanaged`（默认，零开销）/ `Forward` / `Reverse` / `CenterOut` / `EdgeIn`。

- 机制：`Content` 的 sibling 顺序就是 UGUI 绘制顺序。**改动前没有任何 sibling 管理**，首屏看起来「从上到下」只是创建顺序的副作用，池复用后顺序与索引脱钩（池对象保留旧 sibling）。
- 重排方式：按目标绘制顺序依次 `SetAsLastSibling`（n 次），池中 inactive 对象被挤到底层。
- 中心排序按**视口中心**算主轴距离，用 `_renderOrderViewportCenter` 缓存一次 `anchoredPosition`（比较器里不能再读 native 属性）。只在「中心项 index 变化」时重排，不是每帧。
- 距离量化到 1/16 像素 + 用索引 tie-break：`List.Sort` 不稳定，对称位置不给次序键会层级抖动。
- 必须用**布局坐标**而非虚拟索引做键，否则循环列表 `RecenterLoop` 平移周期后整片翻层。
- `ApplyRenderOrder()` 放在 `RefreshVisible` 的 `ApplyItemLayouts` 之后、`RecenterLoop` 之前。
- 多列网格下相邻项不重叠、层级差异不可见，Inspector 只给 3 个选项（`DrawRenderOrder` 里 `centerAvailable = singleVertical || !multiple`）。
- `BringToFront`（选中项临时置顶）讨论后判定网格场景用不上，**未实现**。

改动文件：`UIVirtualList.cs`、`UIVirtualListComponent.cs`、`UIVirtualListComponentEditor.cs`、`Editor/Tests/UGUIVirtualListTests.cs`（5 个用例）、`README.md`。

注：`RecenterLoop` 里的 `RefreshVisible(true)` 因 `_refreshing` 守卫是死代码，recenter 后靠下一帧滚动事件补刷。影响一帧，未修。

## 虚拟列表：单项提权 BringToFront / BringToBack

`UIVirtualList` 加 `BringToFront(int)` / `BringToBack(int)` / `ClearPinned()`，组件层同名转发。

- 索引是**数据索引**（与 `ItemClicked` 一致）。循环列表按 `ToDataIndex` 匹配，一个数据的多个周期副本一起提权 —— 因为 recenter 后虚拟索引会整体平移，存虚拟索引会失效。
- 持久：`_pinnedFront` / `_pinnedBack` 两个 List 记录，`ApplyPinnedOrder()` 在 `ApplyRenderOrder()` 之后重新应用（`RefreshVisible` 末尾）。
- 数据变更跟随偏移：`RemapPinnedIndices` 在 `InsertDatas` / `RemoveRange` 调用点旁边；`SetDatas` 里 `ClearPinned()`。
- `SetPinnedSibling` 先比 `GetSiblingIndex()` 与目标（0 或 `childCount-1`），相同就跳过 —— 否则滚动期间每帧改层级。
- 置底列表倒序遍历应用，保证先调用的更靠下；置顶正序，后调用更靠上。

## 循环列表滑动抽搐：轮播吸附的索引语义错配（已修）

现象：循环 Demo 拖拽松手后内容"抽搐"。与 RenderOrder 无关（改 Unmanaged 仍在）。

根因链：`UIVirtualCarousel.IndexForPosition` 用 `_list.Count`（真实条数 8）遍历 `GetItemLayout(0..7)`，而该方法接受**虚拟索引**（0..23）。滚过第 0 周期后二分永远返回 `count-1`，`padding = itemStart - target` 把目标算到第 0 周期；`ScrollTo` 里 `_start` 先记录当前位置，再 `RefreshForNavigation(7, Start)` **无条件** `SetScrollPositionInternal(start - length)`，把内容瞬移回 716；下一帧 Tick 从 `_start` 插值又拉回 → 一帧内来回跳 = 抽搐。

修复（4 处 `Count` → `RenderCount`）：`IndexForPosition`、`UIVirtualScrollNavigator.ScrollTo` 边界与 `Tick` 越界判断、`UIVirtualList.RefreshForNavigation` 边界。另外 `RefreshForNavigation` 去掉了 `alignment == Nearest` 的条件——**任何 alignment 只要目标已可见就不预跳**（预跳只为把远处目标带进缓冲区，已可见时纯属有害）。组件层新增 `RenderCount` 属性，`ScrollTo` 用它做边界。

`_start` 仍在预跳前记录，远距离导航行为未动。

## 循环周期数改为固定 3

`_loopRepeat` / `LoopCycleCount` 全部删除（含 Inspector 输入、DemoSetup 赋值、两处校验、README 说明）。3 是硬下限：只有中间周期是安全区，少于 3 个会反复反向平移。大于 3 无收益（实例数由视口 + buffer 决定，周期数只拉长 ContentLength）。

## 吸附：惯性结束后触发 + 组件开关

- `UIVirtualCarousel` 拆成 `OnScrollStarted`（清 pending + Cancel）/ `OnScrollEnded`（有惯性则挂 `_pendingSnap`）/ `Tick`（velocity 归零才 `SnapToNearestPage`）。阈值 `IdleVelocitySqr = 1f` 与 ScrollRect 自身 `magnitude < 1` 清零对齐。
- `UIVirtualList.ScrollVelocity` 新增（销毁后返回 zero）。
- **`UIVirtualScrollNavigator.ScrollTo` 开头必须 `StopScrollMotion()`**：原来靠 `RefreshForNavigation` 的预跳停惯性，改成「已可见就不预跳」后惯性没停，`ScrollRect.LateUpdate` 与导航器争位置 → 抽搐。导航器接管滚动本就该自己停。
- 组件层新增 `_carouselEnabled` + `CarouselEnabled` 属性 + `ApplyConfiguredCarousel()`；页长 = `ResolvedItemSize.y + _spacing`，仅竖向单列。Inspector 只在竖向单列时显示。
- Demo 的 `_snapPerPage` 删除，`UIVirtualListDemoSetup` 改为设组件 `_carouselEnabled`。**场景里已存在的 Demo 需要手动勾一次**（旧字段被忽略，组件开关默认 false）。

## 循环拼接处丢失一个间距（已修）

现象：7/8 与 8/8 紧贴，其他卡片都有间距。

根因：`UIVirtualLoopLayout.CycleLength => _inner.ContentLength`，而 `UIFlowLayout.ContentLength` 不包含最后一项之后的间距（`start - MainSpacing + paddingEnd`）。周期步进少一个 spacing，第 0 周期末项底部正好顶到第 1 周期首项顶部。

修复：`UIFlowLayout.MainSpacing` 从 private 改 internal；`UIVirtualLoopLayout` 构造加 `cycleSpacing = -1f`（负数自动从 `UIFlowLayout` 推断，包装自定义布局时显式传），`CycleLength = ContentLength + _cycleSpacing`，`ContentLength = CycleLength * repeat - _cycleSpacing`（总额不再多出末尾间距）。

## 循环归位后整屏空白（已修）

现象：滚到第 0 周期边界外时，视口全空一段。

根因：`RecenterLoop` 原本在 `RefreshVisible` **末尾**调用，`SetScrollPosition(+C)` 平移后调 `RefreshVisible(true)` 想重刷，但 `_refreshing` 仍为 true，那行直接 return。内容平移了、可见项没重分配 → 空白，要等下一次滚动事件才恢复。`CycleLength` 补上间距后平移量精确，旧项完全离开视口，问题才明显。

修复：`RecenterLoop()` 提到 `RefreshVisible` 开头（`UpdateViewportLayout` 之后、算 range 之前），删掉里头那行死代码递归。代价是每次跨周期会重建一屏 Item（走池复用），频率为每滚一个周期一次。

## 吸附模式改为下拉框

`UIVirtualCarouselSnapMode`：`None` / `Nearest` / `First`（floor，回吸本页开头）/ `Last`（ceil，吸下一页；正好页首不动）/ `Inertia`（松手速度方向，< 50px/s 退回最近）。

- `_carouselEnabled` 删除，组件字段换成 `_carouselSnapMode`，属性 `CarouselSnapMode`（setter 会重新应用，None 时 Disable）。
- `EnableCarousel(pageLength, snapDuration, snapMode)` 加第三参数。
- **`_snapDirection` 必须在 `OnScrollEnded` 记录**：吸附发生在惯性归零之后，那时 velocity 已是 0。
- 方向约定：`velocity.y > 0` = 内容上移 = position 增大 = 看后面的项 → `Ceil`。

### 吸附对齐改为按实际项边界（可变高度）

固定页长 `round(position / page)` 在可变高度列表里会把页边界算到项中间，底部对齐时裁掉半截。改为：

- 顶部候选：`start(IndexForPosition(pos))` 与 `start(index+1)`，比较 `pos - start` 与 `nextStart - pos` 取近的。
- 底部候选：`end(IndexForPosition(pos + viewport)) - viewport` 与 `end(index-1) - viewport`，比较距离取近的。
- `Nearest` = 两个候选取近；`First` = 顶部候选；`Last` = 底部候选；`Inertia` 有方向时按 `start(index)`/`start(index+1)`，无方向落 `Nearest`。

`_pageLength` 现仅用于 `SnapTo(page)` / `CurrentPage`，可变高度下这两个仍按固定页长换算，与真实项位置有偏差（未修）。

（后续已一并修复：`UIVirtualCarousel` 彻底删掉 `_pageLength` / `PageLength` / `SetPageLength`，构造函数改为 `(list, snapDuration)`；`CurrentPage` 改为 `IndexForPosition(ScrollPositionValue)`；`SnapTo(index)` 直接 `ScrollTo(index, Start, 0f)`。组件层 `EnableCarousel(snapDuration, snapMode)` 去掉 pageLength 参数——对外接口净减少。测试 `SnapToPageClampsAtEndAndRejectsBadPageLength` 改写为 `SnapToRejectsOutOfRangeAndStopsAtLastItem`。）

## 新增 UpdateDatas：全量刷新保持滚动位置

`SetDatas` 拆成 public 包装 + private `SetDatasCore(datas, scrollToIndex, preserveScroll)`；新增 `UpdateDatas<T>(datas)` 走 `preserveScroll: true`。组件层同名转发。

- 锚点必须在 `ResetActiveItems` **之前**用 `CaptureDataAnchor()` 取（它读 `FirstVisibleIndex`）。
- 收尾复用 `FinishDataMutation(anchor)`：恢复位置、越界夹到末项、原本贴底则继续贴底，只 `RefreshVisible(false)` 不重置。
- 循环列表的虚拟索引锚点跨周期不可靠，`canPreserve` 直接判 false，退化为回中间周期。
- 与 `UpdateData(index, data)` 只差一个字母，命名易混，已在 XML 注释和 README 注明区别。
- 测试：`UpdateDatasKeepsScrollPosition` / `UpdateDatasClampsAnchorWhenDataShrinks` / `SetDatasStillReturnsToTop`。

## 关于「改 count 模式」的结论（未实施）

评估过：`SetDatas` 1000 条 class 的拷贝只占 ~30μs，`RefreshVisible` 重建可见项才是 1~2ms，count 省不掉。且树/分组/分页的行是框架合成的投影，count 模式下业务在 `Bind(index)` 里拿不到 data，必须再开 `GetTreeRow(index)` 之类，接口**净增**。结论：不改，用 `UpdateDatas` 解决真正的痛点（回顶部）。







## ItemSizeProvider（已回滚，未采纳）

评估过组件层加一个「业务直接给尺寸」的委托，跳过 `ForceRebuildLayoutImmediate`。结论：不加。`IUIVirtualListItem.Measure()` 本来就是 `virtual`，模板挂脚本 override 即可覆盖唯一真实场景；再加一个委托只是让「模板无脚本 + 可变高度」这条路径多一个入口，收益不足以扩大 API 面。
